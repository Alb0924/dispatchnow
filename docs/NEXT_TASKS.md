# 下一步任务：接管现有数据库，再进入业务开发

依据当前情况：Windows 11 运行 Spring Boot；虚拟机运行三项中间件；用户已手工创建 project01 的 46 张表；尚无 Flyway 历史。当前项目仍是启动与连接骨架。

## 优先任务 03：数据库迁移接管与数据访问基础

| 子任务 | 交付内容 | 验收 |
|---|---|---|
| 03.1 只读核对 | 运行 database/inspect_existing.sql，按表名、列类型/可空/默认值/生成表达式、索引、外键和 CHECK 比对批准 DDL | 形成明确差异清单；不是只数 46 张表，也不直接比较未经规范化的 SHOW CREATE 文本 |
| 03.2 保留现状 | 数据库备份与结构快照；保留当前正式 DDL 为同源 V1 | 备份可恢复，V1 可在隔离实例的空 project01 执行 |
| 03.3 接入 Flyway | 使用与 Boot 4.1 兼容的 Flyway / MySQL 支持；默认不自动 baseline，禁用 clean | 连错库、未核对结构或历史缺失时清楚失败 |
| 03.4 显式基线 | 确认现有结构与 V1 一致后，用明确的目标连接执行一次 baseline，版本 1 | 已有 46 张表与数据保留，仅新增正确迁移历史；V1 被标记为已覆盖 |
| 03.5 双路径测试 | 隔离空库执行 V1；已有库 baseline 后接 V2；重复启动；修改已应用迁移后的校验失败 | 新空库和接管库的升级路径都可复现，重复启动不重复建表 |
| 03.6 MyBatis 基础 | 锁定兼容 Starter，配置 Mapper/测试，核对 BIGINT、BINARY(32)、DATETIME(3) 和 JSON 映射 | 真实 MySQL 上读写正确，不使用 ORM 自动改表 |

现有库不需要为了使用 Flyway 而删除。显式 baseline 会记录现有数据库起点，版本大于 1 的迁移继续正常执行；历史结构的正确性由接管前核对和可重建 V1 保障，baseline 本身不替人检查字段。

不要把 baseline-on-migrate=true 长期开为默认启动行为。已经存在的 V1 迁移不能回改，后续调整写 V2、V3。若实际表与批准 DDL 不一致，先确定哪一份是最终结构并形成修复方案，再基线化。

上述操作尚未在用户虚拟机上执行。本次只增加了只读检查脚本、DDL 参照和计划，没有向现有库自动写入迁移历史。

## 后续三步

| 顺序 | 任务 | 完成判据 |
|---|---|---|
| 04 | 统一响应、错误码、参数校验、traceId | HTTP 状态和错误码一致，异常不暴露 SQL/凭据；有针对性测试 |

之后进入报价、报价消费和订单创建。暂不并行铺开支付、抢单、轨迹和多单算法；先让身份、权限、数据访问和事务基础可验证。
